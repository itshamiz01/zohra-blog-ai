### 1. Autonomy Modes & Hierarchical Gating

Zohra supports 6 formal autonomy tiers configured at both platform and per-site levels:

| Autonomy Mode | Autonomous Discovery | Autonomous Research | Autonomous Drafting | Autonomous Verification | Autonomous WordPress Publishing | Human Review Required |
|---|---|---|---|---|---|---|
| **OFF** | Disabled | Disabled | Disabled | Disabled | Disabled | Yes (All actions stopped) |
| **MANUAL** | Enabled | Requires Trigger | Requires Trigger | Requires Trigger | Requires Trigger | Yes (Every transition gated) |
| **RESEARCH_ONLY** | Enabled | Autonomous | Blocked | Blocked | Blocked | Yes (Manual draft approval) |
| **DRAFT_ONLY** | Enabled | Autonomous | Autonomous | Autonomous | Blocked | Yes (Publication requires human editor) |
| **AUTO_LOW_RISK** | Enabled | Autonomous | Autonomous | Autonomous | Autonomous (Low-risk only) | Yes for YMYL, financial, medical, or score < 90 |
| **POLICY_CONTROLLED** | Enabled | Autonomous | Autonomous | Autonomous | Policy-driven | Dynamic escalation on risk or divergence |

### 2. Emergency Global Kill Switch (Section 105, 106, 174, 175)

The platform implements an immediate, release-blocking kill switch evaluated before every autonomous worker action:

1. **Trigger Mechanism:**
   - REST API: `POST /api/v1/operations/autonomy/pause`
   - Requires: `UserRole.ADMIN` or `UserRole.SUPER_ADMIN`. (Tested: VIEWER role cannot trigger; denied with HTTP 403).
2. **Governor Circuit Breaker:**
   - In `app/services/autonomy_governor.py`:
     ```python
     if not AutonomyGovernor.is_autonomy_active():
         raise AutonomyPausedError("Autonomous actions are currently halted by emergency kill switch.")
     ```
3. **Bypass Resistance (Section 106):**
   - Direct API calls, queued Celery tasks, scheduled background cron jobs, and task retries invoke `AutonomyGovernor.can_execute(...)`.
   - Verified in `tests/integration/test_audit_attack_scenarios.py::test_emergency_kill_switch_blocks_autonomous_actions`: Any task attempting execution after kill switch activation is immediately aborted without modifying remote state.

### 3. Human Review & Editorial Gates (Section 166, 167)

1. **Anti-Collusion Separation (Section 79):**
   - The Editorial Writer (Part 4) outputs a draft with internal metrics.
   - The Evidence Grounding Verifier (Part 5) independently maps sentences to claims.
   - The Final Audit Package (Part 6) is generated by an independent evaluator. The writer cannot approve its own draft.
2. **Approval Immutability & Content Hash Locking (Section 86, 167):**
   - When an editor approves a draft version via `POST /api/v1/publications/{id}/approve`, the approval record stores `payload_hash = job.content_hash`.
   - If any text is altered after approval, the content hash changes, invalidating the approval token and causing `PublicationCoordinator` to reject dispatch.

### 4. Version Conflict & Human Edit Protection (Section 87)

- When an autonomous optimization job (Part 9) attempts to refresh an existing WordPress post, it inspects the live remote post hash.
- If a human operator has manually modified the post in WordPress since publication, the hashes diverge.
- The publishing engine detects this divergence and raises `VERSION_CONFLICT`, preserving human edits and logging a security audit event.
